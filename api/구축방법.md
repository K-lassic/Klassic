# 구축 방법 — 처음부터 실행까지

> 이 문서는 `api/` 를 처음 받아서 서비스를 띄우는 순서를 한 곳에 모은 것이다. 세부 설명은 각 README 에 있다.
> - 전체 구조 · 담당 → [README.md](README.md)
> - 운영 · 외부 공개 · 엔진 설치 · 백업 → [deploy/README.md](deploy/README.md)
> - 서비스별 설정 · 운영자 명령 → 각 `services/*/README.md`
>
> 명령은 **Git Bash** 에서 `api/` 폴더 기준으로 실행한다. 비밀값(키 · 비밀번호)은 이 문서와 저장소에 적지 않는다. 키 이름과 명령만 적는다.

## 1. 준비물

| 항목 | 확인 방법 |
|---|---|
| Docker Desktop (Windows) 또는 Docker Engine (Linux) | `docker version` |
| Docker Compose v2 이상 | `docker compose version` |
| Git 과 Git LFS | `git lfs version` |
| PowerShell 7 (`pwsh`) — 공개 점검 · 외부 공개 스크립트용 | `pwsh -v` |
| 빈 디스크 여유 20GB 이상 (엔진 설치 중 임시 사용량 포함) | 설치 전에 확인 |
| 인터넷 연결 (엔진 · 이미지 내려받기) | — |

Windows 에서는 저장소를 `C:\project\Klassic` 같은 짧은 경로에 둔다. `AppData\Local\Temp` 아래에서 빌드하면 Compose 가 실패할 수 있다.

## 2. 저장소 받기 (음원은 Git LFS)

```bash
git lfs install
```

```bash
git clone https://github.com/K-lassic/Klassic.git
```

```bash
cd Klassic/api
```

```bash
git lfs pull
```

`git lfs pull` 을 하지 않으면 사운드폰트(`api/shared/soundfonts/*.sf2`)가 작은 포인터 파일로만 받아진다. 연주 기능이 동작하지 않는다.

## 3. `.env` 만들기

`.env` 는 Git 에 올라가지 않는다. `.env.example` 을 복사해서 값을 채운다.

```bash
cp .env.example .env
```

채워야 하는 키 이름은 다음과 같다. 값은 직접 만든다.

| 키 | 값 만드는 방법 · 조건 |
|---|---|
| `API_PUBLIC_PORT` · `API_ADMIN_PORT` | 기본 9603 · 26201. 다른 서비스와 겹치면 바꾼다 |
| `DB_NAME` · `DB_USER` | 임의의 이름 |
| `DB_PASSWORD` · `DB_ROOT_PASSWORD` | `openssl rand -hex 16` 같은 임의 값 |
| `SESSION_SECRET` | 32자 이상. `openssl rand -hex 32` |
| `ADDR_HASH_SALT` | 16자 이상. `openssl rand -hex 16` |
| `DOCKERHUB_NAMESPACE` · `APP_TAG` | 이미지 이름과 태그 (기본값 `klassic`, `dev`) |
| `ENGINES_VOLUME_NAME` | 엔진 볼륨 이름. 새로 설치할 때는 `klassic_engines` 와 다른 이름을 쓴다 (4절) |
| `SERVICE_API_KEY` | 비워 두고, 5절에서 발급해서 채운다 |
| `PUBLIC_BASE_URL` | 외부 공개 주소. 비우면 `http://127.0.0.1:9603` |

`.env` 를 만든 뒤 설정이 맞는지 확인한다. 값은 출력되지 않는다.

```bash
docker compose config --quiet
```

출력이 없으면 정상이다. 오류가 나면 빠진 키 이름이 메시지에 나온다.

## 4. 엔진 볼륨 만들기 (인식 · 연주에 필요)

인식 엔진(오선보 homr, 정간보 jeongganbo-omr)은 이미지에 넣지 않는다. 설치기가 엔진 볼륨에 채운다. 설치는 약 8분 걸린다 (2026-11-03 측정, 이미지 빌드 제외). 설치 뒤 볼륨은 약 5.6GiB 다.

설치기는 운영 볼륨 이름(`klassic_engines`)을 거부한다. 새 설치에서는 새 이름을 정해서 쓴다. 이름은 `.env` 의 `ENGINES_VOLUME_NAME` 과 같아야 한다. 예를 들어 `klassic_engines_new` 로 정한다.

```bash
export ENGINES_VOLUME_NAME=klassic_engines_new
```

```bash
docker volume create "$ENGINES_VOLUME_NAME"
```

```bash
docker compose --profile tools build engines-installer
```

```bash
docker compose --profile tools run --rm --no-deps engines-installer
```

설치기는 고정된 버전과 해시로 엔진을 설치하고, 완료 표식(`INSTALL_MANIFEST.json`)을 남긴다. 중간에 실패하면 완료 표식이 없는 상태로 남으므로, 같은 볼륨에 다시 돌리지 말고 **새 볼륨 이름으로** 처음부터 다시 한다.

설치가 끝나면 `.env` 의 `ENGINES_VOLUME_NAME` 을 같은 값으로 두었는지 확인한다.

## 5. 서비스 띄우기

```bash
docker compose up -d --build --wait
```

`--wait` 는 모든 서비스가 healthy 가 될 때까지 기다린다. 처음에는 이미지 빌드 때문에 수 분 걸릴 수 있다.

확인:

```bash
docker compose ps
```

`web`, `admin`, `frontend`, `model-api`, `db` 가 모두 `healthy` 면 정상이다. `migrate` 는 DB 스키마를 올린 뒤 종료되므로 `Exited (0)` 로 보이는 것이 정상이다.

## 6. 운영자 계정과 서비스 키 만들기

운영자 계정은 웹에서 만들 수 없다. 서버 PC 에서 명령줄로 만든다. 비밀번호는 화면에 나오지 않게 두 번 묻는다 (`-it` 필요).

```bash
docker compose run --rm -it web node dist/tools/createOperator.js --login <아이디> --name <이름>
```

서비스 키는 model-api 를 부를 때 쓰는 열쇠다. 원문은 발급할 때 한 번만 나온다. 나온 값을 `.env` 의 `SERVICE_API_KEY=` 뒤에 붙여 넣는다.

```bash
docker compose run --rm web node dist/tools/issueServiceKey.js --operator <운영자 아이디>
```

`.env` 를 고친 뒤에는 `web` 을 다시 만들어야 새 값을 읽는다.

```bash
docker compose up -d web
```

## 7. 음원 라이선스 확인 (MP3 허용)

음원(MP3)은 이용 조건을 확인한 뒤에 외부 API 로 내보낸다. 확인하지 않으면 외부 예시 홈페이지에서 MP3 요청이 409 `MP3_WITHHELD` 로 막힌다. 확인은 운영자가 한다.

```bash
docker compose run --rm -T web node dist/tools/confirmLicense.js --operator <운영자 아이디> --confirm
```

되돌리기는 `--withhold` 를 붙인다.

## 8. 동작 확인

| 확인 | 명령 · 주소 | 정상 |
|---|---|---|
| 화면 | `http://127.0.0.1:9603/` | 200 |
| 사용자 API | `http://127.0.0.1:9603/api/health` | 200 |
| 인식 API | `http://127.0.0.1:9603/api/v1/health` | 200 |
| 관리자 API (외부에서) | `http://127.0.0.1:9603/admin/login` | 404 (정상) |
| 공개 점검 | `pwsh deploy/check-public.ps1 -Url http://127.0.0.1:9603 -Local` | `모두 통과` |

브라우저에서 가입 → 로그인 → 예시 악보 선택 → 인식 결과 확인 → 내려받기 순서로 한 번 돌려 본다. 첫 인식은 컨테이너를 막 띄운 뒤라 35~47초 걸릴 수 있다. 두 번째부터는 빨라진다.

## 9. 외부 공개 (선택)

외부 사용자가 접속하려면 Tailscale Funnel 을 쓴다. 자세한 절차는 [deploy/README.md](deploy/README.md) 의 「외부 공개」 절을 본다.

```bash
pwsh deploy/funnel.ps1 start -Port 9603
```

공개 주소는 `pwsh deploy/funnel.ps1 status` 로 확인한다. 끝나면 `pwsh deploy/funnel.ps1 stop` 으로 끈다.

## 10. 자주 나는 문제

| 증상 | 확인할 것 | 조치 |
|---|---|---|
| `external volume "…" not found` | `ENGINES_VOLUME_NAME` 과 실제 볼륨 이름이 같은지 | 4절의 볼륨을 만들고 이름을 맞춘다 |
| 업로드는 되는데 인식이 모두 대체 악보 | `docker compose ps` 의 model-api, 2절 LFS | 엔진 볼륨 설치 완료 여부 확인 |
| 업로드가 모두 반려 (`AUTH_KEY_MISSING`) | `.env` 의 `SERVICE_API_KEY` | 6절 서비스 키 발급 후 `web` 재생성 |
| 소리가 나지 않음 | `git lfs pull` 을 했는지 | 2절 다시 실행 |
| `docker compose up` 이 이미지를 다시 만들지 않음 | 이미지 ID 와 컨테이너 ID 가 다른지 | `docker compose up -d --force-recreate --no-deps --wait <서비스>` |
| Windows 에서 빌드가 `bake` 오류로 실패 | 저장소가 `AppData\Local\Temp` 아래에 있는지 | 짧은 경로로 옮겨서 다시 실행 |

**쓰지 않는 명령**: `docker compose down -v` (데이터가 지워진다), `docker system prune` (다른 프로젝트 이미지와 볼륨까지 지울 수 있다).

## 11. 끝낸 뒤

```bash
docker compose ps
```

서비스를 멈출 때는 `docker compose stop` 을 쓴다. 볼륨을 지우는 `down -v` 는 쓰지 않는다. 백업은 [deploy/README.md](deploy/README.md) 의 「백업 · 복원」 절을 본다.
