## 1. 결론

**논문 주제가 된다. 다만 「정간보를 인식하는 API 를 만들었다」로는 어렵고, 「인식 결과를 연주 가능한 악보로 바꿀 때 무엇이 틀어지는지를 잰다」로 잡아야 한다.**

1. **정간보 인식 자체는 우리 기여가 될 수 없다.** 우리 엔진은 선행 논문의 저자들이 공개한 `MALerLab/jeongganbo-omr` 를 고치지 않고 쓴 것이다 `[코드]`. 같은 연구 그룹이 2024~2026년에 인식 · 생성 · 손글씨까지 이미 발표했다(2.1절).
2. **비어 있는 곳은 인식 다음 단계다.** 정간보 인코딩을 MusicXML 로 바꾸는 규칙을 체계적으로 평가한 논문은 이번 검색에서 찾지 못했다. 예비 비교(4절)에서 우리 변환기와 공개 자료의 차이가 **악기에 따라 크게 갈렸다** — 가야금은 음높이가 모두 같았고, 대금은 음 시작점 일치가 0.735 였다.
3. **추천 주제:** 주제 A 「정간보 인식 결과의 오선보 변환 — 시김새 해석에 따른 차이 측정」. 여력이 있으면 주제 B(신뢰도 판정)를 한 절로 넣는다. 가장 빨리 낼 수 있는 것은 주제 C(시스템 논문)지만 독창성이 낮다.
4. **먼저 풀 것:** 정답 악보 확보, 악보 · 엔진 · 데이터 이용 조건 확인, 국악 전공자 검수. 지금 우리 평가셋에는 정간보가 한 장도 없다 `[코드]`.

이 저장소는 **공개(PUBLIC)** 다. 이 문서와 PR 도 누구나 볼 수 있으므로, 아직 발표하지 않은 세부 실험 설계를 여기에 계속 쌓을지는 팀이 정한다(8절).

### 2.4 동향 요약

1. 관심이 **「읽을 수 있나」에서 「표준 지표로 얼마나, 어디가 틀리나」로** 옮겨 갔다.
2. 자료가 적은 전통 기보는 **데이터 공개**와 함께 낸다.
3. 정간보 인식 · 생성은 한 연구 그룹이 앞서 있다. 같은 문제로 성능을 겨루기보다 **그 결과를 쓰는 뒤 단계**가 낫다.
4. 국악에서는 **시김새**가 반복해서 한계로 나온다. 전문가 사이에서도 일치가 낮다.

## 4. 예비 비교 — 주제 A 가 성립하는지 확인

**무엇을 했나.** 공개 데이터셋의 정간보 인코딩 91곡 · 454성부를 우리 변환기(`jeongganbo_convert.py`, `1157299`)에 넣고, 같은 데이터셋이 공개한 MusicXML 과 비교했다. 음의 시작점(온셋)과 그 시작점의 음높이를 세었다. 저장소 밖에서 실행했고 스크립트는 올리지 않았다.

| 악기 | 성부 | 시작점 재현율 | 시작점 정밀도 | 같은 시작점의 음높이 일치 |
|---|---|---|---|---|
| 가야금 | 76 | 0.969 | 0.969 | 1.000 |
| 거문고 | 72 | 0.974 | 0.958 | 1.000 |
| 아쟁 | 33 | 0.991 | 0.973 | 0.991 |
| 해금 | 91 | 0.950 | 0.952 | 0.970 |
| 피리 | 91 | 0.882 | 0.892 | 0.954 |
| **대금** | 91 | **0.735** | **0.861** | **0.887** |
| 전체 | 454 | 0.881 | 0.921 | 0.957 |

**읽는 법**
- 변환 실패는 0건, 성부 수가 어긋난 곡도 0건이다.
- 줄을 뜯는 악기(가야금 · 거문고)는 거의 같고, **관악기(대금 · 피리)에서 벌어진다.** 시김새를 앞 음 높이로 근사하는 우리 규칙이 주된 원인일 것으로 본다 `[추정]` — 기호별로 나눠 확인하지는 않았다.
- **정확도가 아니다.** 비교 대상도 같은 인식 결과에서 규칙으로 만든 것이고 완전히 검수되지 않았다. 「두 변환 규칙이 얼마나 다른가」이다.
- **공개 인코딩은 엔진 출력과 표기가 달라 맞춰 넣었다.** `:0`(정간 전체) → `5`, 빈 칸 → 이음, `:5` 하나뿐이면 앞에 이음 추가, 길이는 1정간 = 점4분음표로 맞춤(우리 기본값은 4분음표). 이 해석은 Claude 가 정한 것이라 본 실험 전에 확인해야 한다.
- 같은 시작점에 음이 여럿이면(꾸밈음 등) 하나만 셌다. 그래서 꾸밈음 차이는 이 표에 다 나타나지 않는다.
- **검사기 확인:** 우리 결과를 일부러 반음 올리면 음높이 일치 0.000, 시작점을 1/8 밀면 재현율 0.001, 길이 배율을 안 맞추면 0.247 로 떨어졌다. 틀린 입력을 잡는다.

**뜻.** 공개 자료만으로도 악기 사이의 차이가 뚜렷해서, 주제 A 는 새 데이터를 만들기 전에 시작할 수 있다. 정답 악보와의 비교(#206)는 여전히 필요하다.

## 5. 논문 주제 후보

### 주제 A (추천) — 정간보 인식 결과의 오선보 변환에서 생기는 차이 측정
- **질문:** ① 같은 정간보를 서로 다른 변환 규칙으로 옮기면 얼마나 달라지나 ② 차이는 어느 악기 · 어느 시김새에서 생기나 ③ 인식 오류와 변환 오류는 최종 악보에 각각 얼마나 남나
- **우리 몫:** 평가 방법과 기호별 오류 분류, 근사 규칙별 비교. 변환기 · 평가 도구 공개
- **자료:** 공개 91곡 + 전공자가 검수한 정답 몇 곡(#206)
- **지표:** 시작점 · 음높이 · 길이 일치, 시김새 종류별 오류, 가능하면 OMR-NED
- **비교 대상:** 공개 MusicXML, 변환 규칙을 하나씩 뺀 우리 변환기
- **위험:** 정답이 없으면 「차이」만 말하고 「맞음」을 말할 수 없다. SejongMusic 에 변환 코드가 있으므로 차별점을 **변환이 아니라 평가**에 두어야 한다.

### 주제 B (A 에 더할 절) — 인식 결과의 신뢰도 판정
- **질문:** 정답 없이 악보 규칙(마디 길이 · 도약 · 율명 비율)과 엔진 확신도로 나쁜 결과를 걸러낼 수 있나
- **지금 부족한 것:** 나쁜 결과 표본. `evalset/README.md` 는 좋음 · 나쁨이 각각 20건 미만이면 보정을 믿지 말라고 적는다.
- **비교:** 엔진 확신도만 쓴 경우, 규칙만 쓴 경우, 둘을 합친 경우(AUC · ECE)

### 주제 C (가장 빠름) — 국악보 변환 · 편집 · 연주 웹 서비스의 설계와 운영
- **내용:** 두 엔진을 한 API 로 묶고 대체 · 미리보기 · 자원 한도를 잰 기록. CPU 전용 환경
- **강점:** 실측 기록이 이미 있다. **약점:** 새로움이 낮고 우물사이와 기능이 겹친다. 사용자 평가가 없으면 약하다.
- **차별점:** 사진 · PDF 에서 시작해 편집 · 국악 음원 연주까지 잇는 점(우물사이 기사에는 사진 인식이 없음 `[추정]`)

### 비교와 추천

| | 새로움 | 지금 자료로 시작 | 전공자 필요 | 기간 `[추정]` | 위험 |
|---|---|---|---|---|---|
| **A** | 중상 | 가능 | 정답 검수에 필요 | 2~3개월 | 중 |
| B | 중 | 어려움 | 일부 | 2~3개월 | 중상 |
| C | 하 | 가능 | 불필요 (평가하면 필요) | 1개월 | 하 |

**추천: A 를 본 논문으로, B 는 자료가 모이면 절로 더한다.** 일정이 급하면 C 를 짧은 발표로 먼저 내고 A 를 이어 간다. 시작 비용이 낮고(공개 자료 · 기존 코드), 안 되더라도 #206 결과가 서비스 개선에 남는다.

**투고 후보** — 이 문서에 나온 가까운 논문이 실린 곳이다. 마감 · 분량 · 게재료는 확인하지 않았다.

## 7. 진행 순서 (제안)

1. **팀 결정:** 주제 · 저자 · 공개 범위 (8절)
2. 못 읽은 선행 연구 원문 확인 → 새로움 다시 판정. **겹치면 여기서 주제를 바꾼다**
3. 공개 91곡으로 A 의 비교를 다시 만들고(표기 맞춤을 검증) 시김새 기호별로 나눈다
4. #206 에서 정답 몇 곡을 만들어 「차이」를 「정확도」로 바꾼다
5. #207(여러 쪽 · 잘린 악보)과 정간보 사진 변형을 B 의 실험으로 쓴다
6. 초안 → 전공자 검토 → 투고

## 8. 팀에 묻는 것

1. 주제 A 를 본 주제로 할지, C 를 먼저 낼지
2. 국악 전공 검수를 누가 할 수 있는지 (정답 악보 몇 곡)
3. 논문 작업 문서를 이 공개 저장소에 둘지, 비공개로 옮길지
4. 국내 학술지와 국제 학회 중 어디를 목표로 할지

## 9. 확인한 것 · 추정 · 하지 못한 것

- **확인:** 위에 `[본문]` · `[코드]` 로 적은 것, 4절의 실행 결과, GitHub 의 라이선스 · 공개 여부.
- **추정:** 새로움 정도, 기간, 시김새가 관악기 차이의 주된 원인이라는 해석. 「찾지 못함」은 이번 검색 범위의 결과이지 「없음」이 아니다.
- **하지 못한 것:** RISS · DBpia · KCI 전수 검색, 유료 · 접근 거부 논문(ACM 2025 최종판, LA-SMT, 판소리 채보 2024 등) 읽기, ISMIR 2026 손글씨 정간보 논문 본문, 투고 마감 확인, 실제 엔진으로 정간보 사진을 인식하는 시험.
- **교차 확인하지 않은 것:** 논문 수치 일부는 하위 에이전트가 페이지에서 읽어 온 값이다. 인용하기 전에 원문과 다시 대조한다.
