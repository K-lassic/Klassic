# 변경방안: 전자 악보(MusicXML · MIDI)로 바로 연주하기

> 2026-11-22 · 검토 요청 문서 (구현 전)
> jsg 의 지시로 Claude 가 코드 · 문서를 읽어 검토하고 이 문서를 작성했다. 「확인」은 코드 · 문서로 본 것이고, 「추정」은 실행해 보지 않고 판단한 것이다.
> 이 PR 은 문서만 더한다. 코드는 바꾸지 않는다. 합의되면 구현 이슈를 따로 만든다.

## 1. 배경 — 왜 바꾸려 하나

- 지금은 사진 · PDF 로 악보를 올리고 **인식(OMR)을 거쳐야만** 연주를 들을 수 있다.
- MusicXML · MIDI 처럼 이미 전자 악보를 가진 사용자도 연주를 들으려면 악보를 이미지로 바꿔 인식에 맡겨야 한다. 인식 시간이 걸리고, 인식 오류로 원래보다 나쁜 악보가 될 수도 있다.
- **제안:** 연주 부분이 인식과 따로 동작하게 해서, 전자 악보를 넣으면 **바로 국악기로 바꿔 들어 볼 수 있는 길**을 지금 기능 옆에 추가한다. 첫 안내에서 「전자 악보 바로 듣기」를 따로 보여 준다.

## 2. 결정이 필요한 것 (팀 검토 요청)

1. **2026-09-29 「직행 없음」 결정을 바꿀지.** `api/shared/upload-rules.json` 과 v0.1.1 `INTERFACES.md` 에 「사용자 업로드는 사진 · PDF 만, MIDI · MusicXML 은 415 `UPLOAD_UNSUPPORTED_TYPE`(G1, 직행 없음)」으로 기록돼 있다. **결정 이유는 문서에서 찾지 못했다.** 이유(예: 인식에 집중, 시험 범위, 품질 책임)를 알려 주면 이 방안에 반영하겠다. — @SonghaeHwang 확인 부탁
2. **범위:** 아래 3절의 방안 A(웹) + B-1(외부 API 안내)부터 할지.
3. **MIDI 를 첫 단계에 넣을지.** MusicXML 만 먼저 받고 MIDI 는 나중에 하는 것을 제안한다(6절 3번).

## 3. 이미 있는 부품 (확인)

필요한 부품 대부분이 저장소에 이미 있다.

| 부품 | 위치 | 지금 쓰는 곳 |
|---|---|---|
| 전자 악보 → MP3 (성부별 악기 지정 · 국악 음원) | model-api `POST /v1/render/mp3` (`routers/render.py`) | backend 내려받기(`renderQueue.ts`) · 외부 키 |
| 인식 없이 바로 완료 | backend `services/directRoute.ts` `completeDirect()` · DB `score_request.route='direct'` | 공유 악보 [이 악보로 작업하기] (`web/shared.ts`) |
| 직행 결과 화면 | frontend `S1Result.vue` 「올린 파일을 인식 없이 바로 악보로 바꿨습니다.」 · `lib/judgment.ts`(직행이면 바로 2단계) | 공유 악보 직행 |
| MusicXML · MIDI 읽고 쓰기 | `@gugak/score-core` `parseMusicXml` · `parseMidi` · `toMusicXml` · `toMidi` | 편집 · 내려받기 |
| 브라우저 재생 · 악기 고르기 | frontend `player/player.ts` · `C4InstrumentPicker.vue` | 편집 · 연주 화면 |

지금 막히는 곳은 다음과 같다(확인).

```
[웹]   S1Upload ─ 사진·PDF ─▶ POST /api/requests ─▶ /v1/omr/* 인식 ─▶ 결과 → 편집 → 연주 / 내려받기
                  └ MIDI·MusicXML → 415 (S1Upload.vue · lib/uploadKind.ts · web/uploadCheck.ts · upload-rules.json)
[웹]   공유 악보 [이 악보로 작업하기] ─▶ completeDirect() (route='direct') ─▶ 결과 → 편집 → 연주      ← 직행이 이미 동작
[외부] POST /v1/performances ─ 사진·PDF ─▶ jobs/performance.py (늘 run_recognition) ─▶ MP3
                  └ MIDI·MusicXML → 415 (uploads.USER_UPLOAD)
[외부] POST /v1/render/mp3 ─ MIDI·MusicXML + instruments ─▶ MP3 (동기 · 최대 120초 · 저장 안 함)      ← 사실상 「연주만」 API
```

## 4. 방안 비교

| 방안 | 내용 | 작업량 (추정) | 장점 | 단점 · 위험 |
|---|---|---|---|---|
| **A. 웹 직행** | 웹 업로드에서 MusicXML(· MIDI)을 받아 `completeDirect()` 로 바로 결과를 만든다. 이어서 편집 · 연주 · 내려받기는 지금 그대로 | 작음~중간 | 부품이 이미 있다. model-api 를 쓰지 않아 인식 한도(G12)에 걸리지 않는다 | 09-29 결정 변경. MIDI 는 MusicXML 로 바꿔 넘겨야 한다 |
| **B-1. 외부 API 안내** | 이미 있는 `POST /v1/render/mp3` 를 API 안내(`S4AApiGuide.vue`)에서 「전자 악보 연주」로 앞에 둔다 | 아주 작음 | 코드를 거의 바꾸지 않는다 | 동기 호출이다. 외부 키는 라이선스 확인 전이면 `mp3_withheld` |
| B-2. `/v1/performances` 직행 | 전자 악보가 오면 `jobs/performance.py` 에서 인식을 건너뛴다 | 중간 | 외부 API 도 비동기 · 결과 보관으로 통일된다 | 작업 · 상태 · 시험이 늘어난다 |
| C. 연주 엔진 별도 컨테이너 | render 부분을 새 서비스로 뗀다 | 큼 | 구조 분리 | Compose · 배포 · 한도 · Runbook 을 새로 해야 한다. 지금 일정에서는 이득이 작다 |

**제안: A + B-1 부터** 하고, B-2 는 수요가 있을 때 한다. C 는 하지 않는다.

## 6. 위험 · 쟁점

1. **결정 변경:** 2절 1번. 이유를 확인한 뒤 진행한다.
2. **프로젝트 주제와 평가:** 주제가 「국악보 변환 · 편집」이라, 인식을 거치지 않는 길이 어떻게 보일지 검토가 필요하다. 「인식이 어려운 악보 · 사용자도 바로 쓸 수 있다」는 장점으로 설명할 수도 있다.
3. **MIDI 품질:** 사람이 연주해 녹음한 MIDI(박자가 맞춰지지 않은 MIDI)는 악보로 바꾸면 음표가 잘게 쪼개지거나 박자가 어긋날 수 있다(추정). 연주는 괜찮아도 편집 화면이 지저분해질 수 있다 → **첫 단계는 MusicXML 만** 받는 것을 제안한다.
4. **정간보:** 전자 악보는 사실상 오선보 형식뿐이다. 정간보는 계속 사진 · PDF 경로를 쓴다.
5. **안전 검사:** `upload-rules.json` 에 musicxml `max_bytes` · `musicxml_structure`(`UPLOAD_MUSICXML_UNREADABLE`)가 이미 있다(확인). `.mxl` 압축을 풀었을 때의 크기 제한은 확인해야 한다.
6. **한도:** 직행은 model-api 를 쓰지 않아 인식 한도에 걸리지 않는다(`shared.ts` 주석). MP3 내려받기는 `/v1/render/mp3` 를 써서 렌더 한도가 그대로 걸린다.
7. **음원 라이선스:** 외부 API MP3 는 `v_mp3_license` 가 확인되기 전까지 `mp3_withheld` 다(확인). B-1 안내 전에 정리가 필요하다.
8. **재생 지연(B3):** 브라우저 첫 재생 때 sf2 를 약 170MB 받는 문제는 이 경로에도 남는다. 「바로 듣기」를 내세우려면 B3 개선을 같이 보는 것이 좋다.

## 7. 첫 안내 (제안)

| 카드 | 넣는 것 | 다음 화면 | 문구(예) |
|---|---|---|---|
| 사진 · PDF 악보 변환 | PNG · JPG · WEBP · PDF + 오선보/정간보 | 인식 → 결과 판별 → 편집 · 연주 | 「종이 악보를 찍거나 PDF 로 올리면 악보로 바꿔 드려요」 |
| **전자 악보 바로 듣기** | MusicXML(.musicxml · .mxl · .xml) (· MIDI) | 바로 연주 · 악기 바꾸기 | 「MusicXML 파일이 있으면 인식 없이 바로 국악기로 들어 볼 수 있어요」 |

전자 악보 카드에서는 오선보/정간보 선택을 숨긴다.

## 8. 진행 순서 (합의되면)

1. 2절 결정 → 구현 이슈 작성. 선행 공용 파일: `upload-rules.json` · `web-api.yaml` · DB 스키마(`file_kind`).
2. A-1: MusicXML 웹 직행, 시험 갱신.
3. A-2: 첫 화면 두 갈래 안내.
4. B-1: API 안내에서 `render/mp3` 를 「전자 악보 연주」로 소개.
5. (선택) A-3 MIDI, B-2 `/v1/performances` 직행, B3 재생 지연 개선.

**완료 기준 (구현 이슈에서 확인할 것)**
- MusicXML 을 올리면 인식 작업 없이 `route=direct` 로 완료되고, 연주 화면에서 악기를 바꿔 재생된다.
- 사진 · PDF 경로와 `/v1/omr/*` · `/v1/performances` 의 반려 규칙은 바뀌지 않는다.
- 깨진 MusicXML 은 422 `UPLOAD_MUSICXML_UNREADABLE` 로 반려된다.

## 9. 참고 — 비슷한 서비스

- Flat.io Embed API(`loadMusicXML` · 성부별 악기)와 alphaTab(실행 중 `.sf2` 교체)이 「악보 → 악기 바꿔 재생」에 가장 가깝다. 둘 다 브라우저 재생 방식이다.
- MuseScore CLI 는 서버에서 MusicXML → MP3 를 만든다.
- 「악보를 보내면 오디오를 돌려주는 공개 REST API」와 국악기 음원 · 정간보를 지원하는 외부 서비스는 검색 범위 안에서 찾지 못했다 → 국악기 연주가 Klassic 의 차별점이다.
- 출처: [Flat Embed API](https://flat.io/developers/docs/embed/api/) · [alphaTab 여러 SoundFont](https://alphatab.net/docs/guides/multiple-soundfonts) · [MuseScore 명령줄](https://handbook.musescore.org/appendix/command-line-usage)
